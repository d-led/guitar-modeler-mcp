# GP-200 backend: data sources and attribution

The Valeton GP-200 backend in this directory is original Go code. The factual
data it embeds — the effect code to name/module mapping, the "inspired by"
hardware descriptions, and the per-effect parameter defaults/names — was
assembled from community reverse-engineering of Valeton's own files and
documentation. The following sources were consulted; where files were copied
verbatim into `testdata/` (binary `.prst` presets only), this is noted there.

## Effect tables (`catalog_data.go`)

Generated by `scripts/extract-gp200-catalog.cjs` from:

- **effect code → name/module**: extracted from Valeton's official GP-200
  `algorithm.xml`, as tabulated in
  [gp200-studio](https://github.com/kabir0st/gp200-studio) (`src/core/effectNames.ts`,
  GPL-3.0). The mapping itself is a fact about a file format, not creative
  expression; the Go tables here are an independent transcription.
- **"inspired by" hardware descriptions**: the community-compiled
  "Valeton GP-200 FX List V2", mirrored in
  [gp200-studio](https://github.com/kabir0st/gp200-studio)
  (`src/core/effectDescriptions.ts`) and
  [valeton-gp200-referencias](https://github.com/Carabantech/valeton-gp200-referencias)
  (`data/en.json`). Trademarks belong to their respective owners.
- **parameter defaults/names**: the same `algorithm.xml`, via gp200-studio
  (`src/core/effectParams.ts`, generated by its `scripts/generate-effect-params.mjs`).

## `.prst` binary format

Reverse-engineered independently by:

- [PRSTDecoder](https://github.com/mikeliddle/PRSTDecoder) (MIT) — the original
  community decoder/encoder, whose `examples/` preset files and format notes
  confirmed the header, metadata and module layout.
- [gp200-studio](https://github.com/kabir0st/gp200-studio) (GPL-3.0) — the most
  complete format documentation (`src/core/PRSTDecoder.ts`, `PRSTEncoder.ts`,
  `controlRecords.ts`, `types.ts`), which pinned down the 72-byte effect blocks,
  15-float parameter arrays, the controls tail and the BE16 checksum.

The offsets and encodings were cross-checked by hexdumping real `.prst` files
from both sources (1224-byte user presets and 1176-byte factory presets).

## Test fixtures (`testdata/`)

See `testdata/ATTRIBUTION.md`. Only binary preset files are copied; they are
device preset data, not code.

## Other consulted references

- [presets-valeton-gp200](https://github.com/victorhugo7691/presets-valeton-gp200) —
  community-shared user presets, used as round-trip fixtures.
- [gp200-preset-builder](https://github.com/fisgonone/gp200-preset-builder) —
  confirmed the preset-name offset (0x44) and that presets are exchanged as
  binary `.prst` files.
- [toneadjust](https://github.com/stonebuzz/toneadjust) — not format-related;
  consulted only to confirm it contains no GP-200 format data.
