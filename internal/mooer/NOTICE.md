# Mooer backend: data sources, attribution and scope

The Mooer backends in this directory are original Go code. They exist so a
guitarist can move a tone they made on one device they own to another device
they own, and understand what a preset contains. Nothing from a vendor's
software ships here: no editor code, no artwork, no documentation, and no
firmware.

## Where the facts came from

### GE150 Pro Li / GE150 Max / GE200 (`catalog.go`, `inspired.go`, `preset.go`, `ge200codec.go`)

- **Model lists and the "inspired by" column** follow the real hardware the
  vendor's own owner's manual names for each model. They were cross-checked
  against the model tables the vendor's GE200 editor (Mooer Studio GE200 2.0.3)
  carries in its own binary: the counts and the order of every module's list
  agree, which is what makes an index mean the same thing on both sides. What
  remains different is the spelling of a few of our labels (the editor writes
  `J800`, `MTL ZONE`, `JET-FLANGER`, where we write `800`, `MTLZONE`,
  `JET FLANGER`).
- **The `.mo` record layout** was reverse-engineered from single-preset files the
  devices themselves export, cross-checked against community converters. The
  checksum rule (the u16 sum of bytes 0x200..0x7FF) is verified against two real
  exports, and the cab block's MIC and TUBE knobs are selectors over the editor's
  own lists (ten microphones, four tube types).
- **Fixtures**: two community presets, described in `testdata/ATTRIBUTION.md`.

### GE100 Pro (`ge100pro.go`, `ge100procodec.go`, `ge100pro_catalog_data.go`)

- **The `.mo` format** was worked out from the behaviour of *Mooer Studio For
  GE100 Pro*, the vendor's own editor: an exported preset is a dump of the frames
  the device hands the editor over USB, and an import replays them. The layout is
  documented in `internal/mooer/ge100procodec.go` in our own words; the Go
  reader and writer are independent implementations, not derived code.
- **Model lists and knob labels** (`ge100pro_catalog_data.go`) are generated by
  `scripts/extract-ge100pro-catalog.cjs` from the model tables the editor ships
  in its own bundle. A preset stores a model *index*, so the order of these
  tables is what makes an index mean anything - without them a name cannot be
  turned into a number the device loads. What is reproduced is interface data:
  model names, the short knob labels shown on screen, and the hardware reference
  the editor records for each model. Neither the editor's code nor its assets are
  copied.
- **Presets**: the writer synthesises the two-frame dump the device expects from
  the documented layout. It does not embed a vendor, factory or third-party
  preset; the committed fixture is this project's own reference tone.
- **Verifying against hardware**: the reader can be checked against a preset
  exported from a device the developer owns, by setting `MOOER_GE100PRO_EXPORT`
  (see `testdata/ATTRIBUTION.md`). No such export is redistributed here.

## Scope and limits

- **Interoperability only.** The purpose is reading and writing preset files for
  hardware the user already owns, and porting tones between such devices. No
  copy protection, licence check, firmware or account mechanism is touched or
  bypassed; nothing here defeats a technical protection measure.
- **No affiliation.** This project is not affiliated with, endorsed by or
  sponsored by Mooer Audio or any other brand mentioned. Product names, model
  names and trademarks belong to their respective owners and are used only to
  describe what a preset contains ("modelled after ..."), never to imply
  endorsement.
- **Taking it down is easy.** If a rights holder objects to any table or fixture
  in this directory, delete the generated data file (or the fixture) and
  regenerate/remove the affected feature; the code is written so the data it
  needs is confined to those files.
- **No vendor EULA was found to cite.** As of this writing neither
  mooeraudio.com nor the editor app bundle publishes a licence agreement or terms
  of use, so the contractual position could not be checked against a document.
  Anyone redistributing this project commercially should satisfy themselves on
  that point for their jurisdiction.
